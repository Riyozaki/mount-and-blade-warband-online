# Mount & Blade: Warband Online Co-op — Архитектура, Дизайн систем и План разработки

> **Формат проекта:** Полноценная кооперативная кампания Кальрадии со свободной песочницей (Co-op + PvP Sandbox, от 2 до 16 игроков одновременно, до 32 персистентных персонажей в одном мире).  
> **База:** Mount & Blade: Warband 1.174 + Warband Script Enhancer 2 (WSE2 v1.1.5.4+) + собственный серверно-клиентский стек (Module System + Lua 5.1 + C/C++ оркестратор и сетевой прокси) + методология и инструменты синхронизации из [`cranebeaker/coop-anything`](https://github.com/cranebeaker/coop-anything).

## 1. Видение проекта и ключевые требования

1. **Полноценная кампания Кальрадии онлайн:** все игроки находятся одновременно на одной живой глобальной карте с ИИ-лордами, королями, караванами, бандитами, деревнями, замками и городами.
2. **Свободная песочница (Co-op + PvP):**
   - Друзья могут объединяться в **Братство / Альянс**, вместе бить бандитов, выполнять квесты, приходить друг другу на помощь в разгар боя, служить одному королю или основать общее королевство (где один игрок — Король, а друзья — его реальные Лорды и Маршал с собственными замками и деревнями).
   - Одновременно песочница полностью свободна: игроки вправе служить разным враждующим королевствам, перехватывать друг друга на глобальной карте, осаждать замки друг друга и сходиться на поле боя армия на армию.
3. **Никакой жёсткой завязки на Steam:** мод должен одинаково работать на Steam, GOG и автономных (Standalone) сборках игры 1.174 — по локальной сети (LAN), через виртуальные сети (Radmin VPN, ZeroTier, Tailscale), напрямую по IP или через встроенный однопортовый UDP-туннель/релей.
4. **Установка, обновление и удаление «в пару кнопок»:** единый установщик сам находит папку Warband, ставит всё необходимое, при выходе новой версии чисто удаляет устаревшие файлы без потери сохранений, а деинсталлятор возвращает папку оригинальной игры в первозданное состояние.
5. **Инженерная надёжность с первого дня:** мы сначала проектируем и пишем всю кодовую базу модульно, сопровождая каждый узел офлайн-компилятором, статическим анализатором сетевых пакетов и headless-симулятором синхронизации из `coop-anything`, чтобы к этапу живых тестов не прийти с сотнями скрытых рассинхронов и дюпов.

## 2. Универсальность (Steam / GOG / Standalone) и безопасность без привязки к Steam

Многие кооп-моды делают ошибку, завязывая сеть и сохранение персонажей исключительно на `steam_api.dll` и `SteamID`. Из-за этого игроки на GOG / Standalone версиях или в локальной сети не могут ни подключиться, ни сохранить своего героя.

Мы решаем это архитектурно чисто и без какого-либо взлома DRM или модификации защиты самой игры:

1. **Движок WSE2 (`Warband Script Enhancer 2`):**
   - Официально распространяется как автономное расширение движка поверх установленного Warband 1.174 и не требует наличия `steam_api.dll` для запуска клиента или выделенных серверов (`add_to_game_servers_list 0` — штатный локальный/приватный режим выделенного сервера Warband).
2. **Собственная криптографическая идентификация игрока (`Player Identity Key`):**
   - При первом запуске нашего лаунчера создаётся локальный криптографический ключ игрока (`%APPDATA%\WarbandOnlineCoop\identity.key` — пара ключей Ed25519 + публичный `player_uid`).
   - При входе на сервер кампании клиент подписывает одноразовый `nonce` сервера.
   - **Зачем это нужно:** даже без Steam никто в локальной сети или Radmin VPN не сможет поменять ник в профиле на чужой и зайти за твоего прокачанного персонажа. А сам владелец может в 1 клик экспортировать свой `identity.key`, чтобы перенести персонажа на другой ПК.
3. **Универсальный сетевой транспорт (`CoopNetProxy`):**
   - **Режим 1 (Универсальный — LAN / Radmin VPN / ZeroTier / Прямой IP):** работает вообще везде без внешних сервисов. Весь трафик мультиплексируется через **один UDP-порт** хоста (по умолчанию `7240`), поэтому не нужно вручную пробрасывать диапазон из 6–8 портов для серверов битв.
   - **Режим 2 (Опциональный UDP-релей по коду комнаты):** лёгкий ретранслятор пакетов для игры через интернет за NAT без VPN и без проброса портов.
   - **Режим 3 (Опциональный Steam P2P модуль):** подгружается динамически *только* если обнаружен запущенный Steam и игроки хотят приглашать друг друга через список друзей Steam. Если Steam нет — модуль просто не загружается, всё работает штатно через Режим 1/2.

## 3. Высокоуровневая архитектура мода

Движок Warband устроен так, что один серверный процесс в один момент времени может вести **либо** стратегическую глобальную карту (`mb_warband_wse2_dedicated_campaign.exe`), **либо** одну тактическую 3D-сцену (`mb_warband_wse2_dedicated.exe`). Поэтому архитектура строится как единый координируемый узел из 4 слоёв:

```
┌────────────────────────────────────────────────────────────────────────────┐
│                        ХОСТ / СЕРВЕРНЫЙ УЗЕЛ                               │
│                                                                            │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │ 1. CoopHostSupervisor (Управляющий процесс + Единый UDP-шлюз :7240)  │  │
│  │    • Запускает Campaign Server и динамический пул Battle-серверов    │  │
│  │    • Держит локальную шину IPC между Картой и Боями                  │  │
│  │    • Мультиплексирует сеть (1 внешний порт -> внутренние серверы)    │  │
│  │    • Управляет ротацией бэкапов и атомарным сохранением мира         │  │
│  └───────────────┬──────────────────────────────────────┬───────────────┘  │
│                  │ IPC (локальный сокет)                │ IPC              │
│                  ▼                                      ▼                  │
│  ┌───────────────────────────────┐      ┌───────────────────────────────┐  │
│  │ 2. Campaign Server            │      │ 3. Scene / Battle Server Pool │  │
│  │ (dedicated_campaign.exe)      │      │ (1..N процессов dedicated.exe)│  │
│  │ • Глобальная карта Кальрадии  │      │ • Полевые битвы и подкрепления│  │
│  │ • Время, ИИ-лорды, дипломатия │      │ • Осады (лестницы, башни)     │  │
│  │ • Экономика, деревни, города  │      │ • Деревни, логова бандитов    │  │
│  │ • Квесты, спутники, политика  │      │ • Турниры, дуэли, побеги      │  │
│  │ • Lua-хранилище профилей/мира │      │ • Точный расчёт потерь/опыта  │  │
│  └───────────────────────────────┘      └───────────────────────────────┘  │
└──────────────────────────────────┬─────────────────────────────────────────┘
                                   │ Сеть (LAN / VPN / Direct IP / Relay)
                                   ▼
┌────────────────────────────────────────────────────────────────────────────┐
│                        КЛИЕНТ ИГРОКА (У всех участников)                   │
│  • CoopLauncher.exe (Выбор роли: «Играть» / «Хостить мир», ник, IP/комната)│
│  • Локальный клиентский прокси-помощник (бесшовный прыжок Карта <-> 3D-бой,│
│    автоподстановка токена и пароля комнаты, синхронизация адресов)         │
│  • mb_warband_wse2.exe + модуль Modules/CalradiaOnline/                    │
└────────────────────────────────────────────────────────────────────────────┘
```

### Почему выделение `CoopHostSupervisor` с локальным прокси — ключевое решение:
- Игроку-хосту не нужно открывать 5 чёрных консольных окон — супервизор запускает их в фоне в тихом режиме, следит за их здоровьем и выводит единый аккуратный статус в лаунчер.
- Battle-серверы не жрут память впустую: 1 дежурный слот прогрет сразу, а слоты №2, №3, №4 поднимаются за ~1.5 секунды только если разные игроки одновременно вступили в разные битвы в разных концах карты.
- Решается классическая болезнь кооп-модов Warband с потерей пароля сервера и выбросом в главное меню при переходе из карты в бой и обратно: локальный прокси клиента прозрачно переключает поток пакетов между `Campaign` и нужным `Battle` слотом.

## 4. Переработка синглплеерного ядра Warband под мультиплеер

В оригинальном Module System вся логика написана вокруг единственного игрока: везде зашиты `trp_player` (ID 0), `p_main_party` (ID 0), единственная фракция `fac_player_faction` и сотни глобальных переменных `$g_*`. Если это не заменить системно, ломаются вассалитет, квесты, свадьбы и королевства.

### Наша серверная модель данных:

| Сущность в сингле | Как реализуется у нас в Коопе | Зачем это нужно |
|---|---|---|
| `trp_player` (один герой) | Статический пул героев **`trp_coop_hero_0` .. `trp_coop_hero_31`** с флагом `tf_hero` | Каждый игрок имеет свои атрибуты, 42 навыка, владение оружием, лицо, экипировку, 96 слотов инвентаря, слоты отношений с лордами и леди, и не умирает навсегда (падает раненым). |
| `p_main_party` (один отряд) | Динамически спавнящиеся партии игроков, связанные через WSE2 `player_set_party_id` / `party_get_player_id` | Движок WSE2 нативно реплицирует координаты партий на карте и даёт каждому игроку управлять своим отрядом. |
| `fac_player_faction` и `fac_player_supporters_faction` | Пул личных фракций **`fac_coop_player_0..15`** + пул королевств игроков **`fac_coop_kingdom_0..15`** | Игрок А может быть в мире со Свадией, пока Игрок Б грабит свадийские караваны; каждый игрок может присягнуть своему королю или создать своё королевство. |
| Глобальные переменные `$player_honor`, `$player_right_to_rule`, `$g_talk_troop`, `$players_kingdom` и др. | Перенесены в **слоты `trp_coop_hero_<i>`** + дублируются в **серверном JSON/Lua-состоянии** | Исключает перезапись данных одного игрока действиями другого. На клиенте `$g_*` используются только как локальный кэш рендера текущего окна. |
| Одиночная таблица квестов `qst_*` | **Серверный реестр инстансов квестов** в Lua (`quest_instances[]`), проецируемый каждому клиенту в его локальный журнал | Два игрока могут параллельно выполнять одинаковые типы заданий в разных городах без взаимных поломок. |
| Нативные окна `Inventory`, `Party`, `Character` | **Серверно-авторитарные презентации + перехват `wse_window_opened`** | Клиент отправляет только *команду-намерение* (`купить`, `переложить`, `повысить юнита`, `прокачать навык`); сервер проверяет правила, применяет изменение и присылает подтверждённый дифф. |

## 5. Проработка всех игровых систем Warband до мелочей

Ниже зафиксирована точная механика работы **каждой** системы оригинального Mount & Blade: Warband в кооперативном режиме.

### 5.1. Создание персонажа, знамя, прокачка и книги

- **Генерация биографии (Анкеты старта):**
  - Полная классическая цепочка: *Пол → Кем был отец (обедневший дворянин, купец, ветеран, охотник, кочевник, вор) → Раннее детство → Юность → Причина выхода в свет*.
  - Сервер сам вычисляет по таблице анкеты итоговые статы, навыки, оружейные очки, **стартовое золото, стартовую известность (`Renown`), честь (`Honor`) и стартовый набор экипировки + провизии** (исключая чит-подмену статов с клиента).
  - **Выбор стартового города:** Правен, Рейвадин, Тир, Саргот, Джелкала или Шариз (включая стартовое объединение: опция *«Начать в одном городе с другом X»*, чтобы друзья с первой минуты оказались рядом!).
  - **Стартовая цепочка торговца (брат купца):** адаптирована под кооп как опциональный быстрый квест в стартовом городе без заморозки мира (логово разбойников открывается как персональная или совместная с друзьями мини-миссия).
- **Редактор лица и выбор знамени:**
  - `face_keys` профиля передаются на сервер и применяются к `trp_coop_hero_<i>`, отображаясь в диалогах, окне отряда и 3D-боях.
  - Любой игрок может выбрать знамя с первого дня (по желанию настройки сервера — либо сразу для удобства коопа, либо классически при получении дворянства / известности 150+). Выбранный баннер закрепляется за игроком, рисуется над отрядом на карте, на щитах его воинов и над его замками, а дубликаты у ИИ-лордов автоматически переназначаются свободными гербами.
- **Прокачка характеристик и навыков:**
  - Нажатия `+` на атрибутах, навыках и владении оружием отправляют запрос на сервер; сервер проверяет свободные очки и потолок навыка (` атрибут / 3 `, `Weapon Master`) и сохраняет профиль.
  - Корректно работают все **3 категории навыков**:
    - *Личные* (`Ironflesh`, `Power Strike`, `Power Draw`, `Power Throw`, `Shield`, `Athletics`, `Riding`, `Horse Archery`, `Persuasion`);
    - *Лидерские* (`Leadership`, `Prisoner Management`, `Inventory Management`) — берутся строго от героя-владельца отряда;
    - *Отрядные* (`Spotting`, `Path-finding`, `Tracking`, `Tactics`, `Trainer`, `Engineer`, `First Aid`, `Surgery`, `Wound Treatment`, `Looting`, `Trade`) — берётся максимальное значение среди самого игрока и здоровых спутников его отряда + бонус лидера (`+1..+4`, если сам игрок прокачал этот навык!).
- **Чтение книг и книготорговцы:**
  - Книги со стат-бонусами (при нахождении в инвентаре, например *De Re Militari*) работают сразу.
  - Читаемые книги: игрок выбирает книгу в меню Лагеря; прогресс чтения (`0..100%`) хранится в слоте предмета/персонажа и начисляется серверным тиком, когда этот игрок **ждёт в лагере или отдыхает в городе/замке** (требуемый `INT` проверяется на сервере).

### 5.2. Глобальная карта, время, разведка, лагерь и выход из игры

- **Течение времени и консенсусное ускорение:**
  - Базовая скорость мира на сервере — **`1.0x`** (настраиваемо в `coop_settings.ini`, например `0.8x` для размеренной игры).
  - У каждого игрока в углу экрана компактная панель времени: дата, время суток и кнопки желаемой скорости `[Пауза] [1x] [3x] [5x]`.
  - **Правило консенсуса:** если *все* подключённые игроки включили ускорение (или стоят на отдыхе в городе/лагере/осаде), сервер автоматически включает `3x` / `5x`. Как только **хотя бы один** игрок снимает ускорение, вступает во встречу на карте или замечает врага вблизи — скорость мгновенно возвращается на `1x`!
  - **Кооперативная пауза:** хост (или голосование игроков) может поставить мир на честную паузу (например, отойти на перерыв).
- **Иконки партий на карте:**
  - Сервер динамически обновляет иконку партии каждого игрока: всадник (если в слоте коня экипирована лошадь), пеший воин (если без коня), шатёр (в режиме лагеря), корабль (при переправах в модах).
- **Скорость отряда, разведка (`Spotting`) и следы (`Tracking`):**
  - Скорость отряда на сервере учитывает `Path-finding`, долю кавалерии, размер армии, боевой дух, день/ночь, лес/степь/снег, вес груза в инвентаре и наличие вьючных лошадей в сумке (компенсирующих вес товаров).
  - Туман войны работает честно для каждого игрока по его `Spotting` (+ опция в настройках Братства: **«Общая разведка союзников»**, чтобы друзья видели отряды, замеченные товарищем).
  - Следы партий (`Tracking`): сервер передаёт клиенту ближайшие треки с возрастом, численностью и направлением в зависимости от уровня `Tracking` отряда игрока.
- **Система Братств (Союзов игроков):**
  - Игроки могут создать группу/братство прямо в интерфейсе на карте: видеть маркеры друзей через всю Кальрадию, быстро следовать за отрядом друга (`Сопровождать`), делиться разведкой и автоматически заходить за одну сторону в боях.
- **Безопасный выход (`Logout`) и защита от `Alt+F4` из боя:**
  - Если игрок выходит в мирной обстановке (в городе или в чистом поле вдали от погони), его отряд сохраняется в профиль и аккуратно убирается с карты до следующего входа.
  - Если за игроком вплотную гонится враг или уже открыто окно перехвата/идёт бой, действует **таймер честного выхода (30–60 сек)**: мгновенное закрытие игры не спасает отряд от уже начавшейся схватки.

### 5.3. Встречи на карте, полевые сражения, подкрепления, Хирургия, плен и лут

- **Перехват и диалоги на глобальной карте (Map Encounters):**
  - При сближении двух партий на карте они встают в состояние *Encounter* (остальной мир продолжает жить!).
  - В зависимости от того, кого встретил игрок, открывается полноценное серверное меню/диалог:
    - **Бандиты / Дезертиры:** бой, попытка откупиться динарами, автобой, отступление под прикрытием арьергарда.
    - **ИИ-лорды и Короли:** мирная беседа (узнать где лорды, взять квест, предложить мир/присягу, обсудить политику), требование сдаться или атака, совместная атака если рядом друг.
    - **Караваны и Крестьяне:** узнать цены в городах, потребовать пошлину, ограбить или сопроводить.
    - **Отряд другого игрока:** открыть **Окно обмена**, вызвать на дружеский спарринг-поединок, пригласить в Братство / принести вассальную присягу ИЛИ **напасть в PvP**, если фракции враждуют (или включён свободный PvP)!
- **Динамический вход в уже идущую битву (Live Drop-in Reinforcements):**
  - Как только начинается любой бой (Игрок vs ИИ, Игрок vs Игрок, или ИИ vs ИИ, к которому подошёл игрок), на глобальной карте создаётся узел битвы со скрещёнными мечами и подписью сторон: `«Битва: Отряд А (55) vs Граф Кларгс (84)»`.
  - Любой другой игрок, добежавший по глобальной карте до этой точки, нажимает *«Присоединиться к стороне А / стороне Б»*:
    1. Campaign Server резервирует его отряд в списке участников боя и отправляет `LIVE_REINFORCEMENT` пакет на соответствующий Battle Server.
    2. Клиент второго игрока автоматически заходит прямо в идущую 3D-сцену!
    3. Сам герой спавнится в ближайшем окне подкрепления (или сразу у края карты с флажком подкрепления), а его солдаты вливаются в очередь волн подкреплений его стороны!
- **Тактическое командование в 3D-бою:**
  - У каждого игрока **собственные группы войск (дивизии 1–9)**: приказы Игрока А (`F1–F7`) двигают *войска Игрока А*, не ломая строй *войск Игрока Б*.
  - В меню `Tab` / панели тактики есть переключатель **«Передать командование войсками лидеру стороны»**, если друзья хотят, чтобы один тактик управлял всей объединённой армией, пока остальные рубятся в кавалерийской атаке.
  - Если героя игрока выбили в бою (0 HP), он не вылетает с сервера, а переходит в удобную **тактическую камеру наблюдения** за союзниками и своими продолжающими бой войсками (с возможностью по желанию настройки сервера «вселиться» в одного из живых солдат своего отряда в стиле *Body Sliding*).
- **Честная математика потерь, `Surgery` (`Хирургия`) и `First Aid`:**
  - В бою каждый заспавненный агент хранит тег `owner_party_id` и `troop_id`.
  - При смертельном ударе тупым оружием агент всегда оглушается (ранен / потенциальный пленный). При смертельном ударе острым оружием сервер боя проверяет шанс спасения по **`Surgery` именно того отряда, которому принадлежит этот солдат** (`25% база + 4% × эффективный навык Хирургии отряда`).
  - После боя к героям и спутникам применяется `First Aid` (восстановление части потерянного в бою HP).
- **Итоги битвы: Опыт, Золото, Пленные, Трофеи (Лут) и Лорды:**
  - **Опыт (`XP`) и Известность (`Renown`):** начисляются пропорционально сложности боя (`Battle Advantage`) и вкладу участников + личный опыт за собственные фраги каждого героя и спутника.
  - **Пленные:** оглушённые враги распределяются между победителями с учётом лимита `Prisoner Management` (5 пленных за уровень навыка). Если у Игрока А слоты полные, оставшиеся пленные автоматически предлагаются союзному Игроку Б!
  - **Трофейный лут предметов (`Item Loot`):** сервер генерирует персональную выборку трофеев для каждого участника победы с учётом его навыка `Looting` и ценности снаряжения разбитых врагов — каждый игрок спокойно забирает свои трофеи на карте, не задерживая остальных.
  - **Побеждённые лорды:** стандартный ролл Warband (шанс сбежать vs попасть в плен). Инициатор/победитель выбирает: взять лорда в кандалы (ради выкупа) или благородно отпустить (`+Honor`, `+Relation`).
- **Поражение игрока и кооперативный плен:**
  - Вместо скучного многодневного экрана ожидания в сингле:
    1. Пленённый игрок прикрепляется как пленник к отряду победителя (ИИ-лорда, бандитов или другого игрока!).
    2. Друг на глобальной карте видит, кто увёл товарища, и может **догнать врага и отбить друга в бою**, либо **выкупить его через посредника/диалог с лордом**.
    3. Если пленника посадили в темницу замка/города — друг может пробраться в город и запустить **кооперативную миссию Побега из тюрьмы** (бой со стражником темницы и прорыв со двора!).
    4. Если спасать некому, через короткий таймер (1.5–2.5 реальные минуты, ускоряемый навыками) срабатывает побег с частичной потерей золота и багажа, как в оригинале.

### 5.4. Инвентарь, экран отряда, еда, боевой дух, бюджет и обмен между игроками

- **Инвентарь и экипировка:**
  - Полная поддержка 4 оружейных слотов, 4 слотов брони, коня, слота еды и до 96 слотов сумки (`Inventory Management` даёт +6 слотов за уровень) с сохранением всех модификаторов (`Lordly`, `Masterwork`, `Balanced`, `Rusty`, `Swaybacked`, количества стрел и свежести еды).
  - Каждая операция перемещения/выброса предмета проходит серверную сверку по версии снимка (`snapshot_epoch`), полностью исключая дюпы при быстром закрытии/открытии окна или лагах сети.
- **Экран отряда и обучение (`Trainer`):**
  - Повышение солдат по веткам развития проверяет на сервере: количество готовых к повышению в стеке, требуемое золото за апгрейд и наличие коней (для модов, где конница требует лошадь).
  - Каждую полночь (`00:00` игрового времени) на сервере срабатывает навык **`Trainer`** самого героя и всех его спутников, начисляя опыт всем солдатам более низкого уровня в его отряде.
- **Провизия, рацион и порча продуктов:**
  - Каждые 14 игровых часов отряд потребляет еду сообразно численности армии.
  - Учитываются все бонусы к боевому духу от разнообразия продуктов (зерно, хлеб, вяленое мясо, копчёная рыба, сыр, колбасы, мёд, фрукты, капуста, масло и свежая говядина/курятина со сроком годности). При голоде падает боевой дух.
- **Боевой дух (`Morale`) и дезертирство:**
  - Индивидуальный расчёт для каждого игрока: база + `Leadership` + разнообразие еды + недавние победы − размер армии − долг по жалованию − штраф за солдат фракции, с которой сейчас идёт война. При критически низком духе ночью часть солдат дезертирует.
- **Еженедельный финансовый отчёт (Бюджет):**
  - Раз в 7 игровых дней сервер рассчитывает баланс каждого игрока: жалование отряда, половинное жалование гарнизонов в его замках/городах, доходы от деревень/городов, пошлины караванов, прибыль от городских цехов, контракт наёмника и штраф налоговой неэффективности (`Tax Inefficiency` при большом числе владений). Если игрок в этот момент в 3D-бою — сводка аккуратно показывается сразу после выхода на карту.
- **Прямой обмен между игроками (`Player Trade`):**
  - Встретившись на карте или находясь в одном городе/замке, два игрока могут открыть окно безопасного бартера: передать друг другу динары, оружие, броню, еду, лошадей, регулярных солдат и пленных (с двухэтапной кнопкой *«Зафиксировать предложение» → «Подтвердить сделку»*).

### 5.5. Города, деревни, торговля, цеха, таверны, арена и совместные турниры

- **Живая мировая экономика и магазины:**
  - Товары и золото у оружейников, бронников, конюхов и торговцев товарами хранятся на сервере и обновляются раз в неделю по экономике Кальрадии (с учётом приходящих караванов и крестьян!).
  - Цена покупки/продажи вычисляется **строго на сервере** с учётом `Trade` отряда игрока и отношений с городом.
  - Работает действие *«Оценить местные цены» (`Assess local prices`)* — тратит несколько игровых часов и подсказывает выгодные торговые маршруты.
- **Производственные предприятия (Цеха в городах):**
  - Каждый игрок может независимо открыть по одному предприятию в каждом из 22 городов (красильня бархата, кузница, пивоварня, маслобойня, кожевня, пекарня и т.д.) при хороших отношениях с лордом города и гильдмейстером.
  - Можно управлять складом цеха (продавать продукцию автоматически или копить сырьё/товар в сундуке мастера цеха). Если фракция игрока воюет с владельцем города — доходы цеха арестовываются до заключения мира, точно как в оригинале.
- **Таверны и жизнь города:**
  - Полноценный выбор: быстрые действия через меню города ИЛИ совместный вход в 3D-сцену таверны/улиц с друзьями!
  - В тавернах работают: отряды наёмников (общий городской слот, обновляемый со временем), выкупщики пленных (`Ransom Brokers` — продажа пленных по рангу + выкуп пленённых спутников и друзей), странники (слухи о местонахождении спутников и претендентов), книготорговцы, барды (разучивание стихов для леди), фермеры с просьбой спасти деревню, пьяные задиры и ночные наёмные убийцы (посланные враждебными лордами!).
  - Ночные засады бандитов при входе в город/деревню и попытка тайно пробраться во вражеский город в плаще с посохом (`Sneak into town`).
- **Арена, тренировочные поля и Совместные Турниры:**
  - На тренировочных полях (`Training Fields`) на карте можно спарринговаться со своими бойцами и с друзьями для прокачки опыта отряда.
  - На городской арене работают тренировочные бои на выживание за динары.
  - **Мультиплеерные Турниры (`Tournaments`):** если в городе идёт праздник/турнир, все находящиеся в городе игроки могут записаться в одну турнирную сетку (6 раундов с ИИ-лордами, именными бойцами и живыми друзьями!), делать ставки на себя перед каждым раундом и сражаться за главный приз, `+20 Renown` и право посвятить победу прекрасной даме!
- **Деревни и скот:**
  - Наём рекрутов в деревнях зависит от личного отношения конкретного игрока с этой деревней (и обновляется индивидуальным пулом/кулдауном с учётом процветания деревни).
  - Покупка продуктов и скота у старосты, гон стада по карте (`Гнать вперёд`, `Следовать за отрядом`, `Остановить`, `Забить часть голов на свежее мясо`).
  - Враждебные действия: принудительный сбор припасов, угон скота и **грабёж/сожжение деревни** (занимает реальные игровые часы на карте — в это время лорд-владелец или другой игрок может прискакать на защиту деревни, и начнётся бой среди деревенских домов без лошадей у атакующих, как в оригинале!).

### 5.6. Уникальные спутники (Companions) и офицеры

- Все **16 классических спутников Кальрадии** (Борча, Марнид, Имира, Рольф, Бахештур, Фирентис, Дешави, Мательд, Алаен, Бундук, Катрин, Джеремус, Низар, Лезалит, Артеминер, Клети) живут в едином мире и путешествуют по тавернам.
- Если Игрок 1 нанял Джеремуса, Джеремус находится в отряде Игрока 1 (уникален для мира).
- Полностью сохраняются и синхронизируются: инвентарь и экипировка спутника, прокачка его статов/навыков, жалобы на нелюбимых напарников/грабежи деревень, отправка спутника в разведку или за `Right to Rule` (с возвратом в отряд владельца через положенное число дней) и возможность пожалования спутнику феода (превращение спутника в полноценного лорда твоего королевства!).
- **Дополнительная кооп-опция:** при игре большой компанией (4–16 человек) в настройках мира можно включить спавн в тавернах **наёмных офицеров-специалистов** (лекарь, инженер, следопыт, квартирмейстер), чтобы каждому игроку хватило профильных помощников.

### 5.7. Инстансируемая система квестов

Серверный менеджер квестов поддерживает полный спектр заданий с таймерами, наградами, изменениями отношений и кооперативным выполнением:

1. **Квесты Гильдмейстеров городов:** перегнать стадо скота, сопроводить караван, доставить эль/вино, выследить и уничтожить конкретную шайку мародёров/бандитов (засчитывается владельцу квеста и помогавшим в бою союзникам!), спасти похищенную девушку (выкуп или бой), примирить двух враждующих лордов, разобраться с ночными бандитами в городе.
2. **Квесты Старост деревень:** привезти мешки зерна, пригнать коров, **обучить крестьян рукопашному бою и вместе отразить налёт бандитов на деревню**.
3. **Квесты Лордов и Королей:** доставить письмо, собрать налоги с феода (с возможностью оставить часть себе с риском гнева лорда), обучить для лорда элитных солдат его фракции, поймать вражеского лазутчика, спасти родственника/лорда из вражеской темницы, одолжить спутника на неделю, захватить пленных вражеской державы, спровоцировать пограничный конфликт.
4. **Военные поручения Маршала:** следовать за армией королевства, провести разведку вокруг трёх вражеских крепостей, пригнать провиант (скот) для голодающего войска.
5. **Квесты Прекрасных Дам:** защитить честь дамы на дуэли против клеветника-лорда, спасти пленённого отца/брата.

### 5.8. Осады крепостей и городов (лагерь, инженерия, штурм и оборона)

- **Осадный лагерь на карте:**
  - При начале осады сервер определяет тип инженерных осадных средств самой сцены замка/города (**штурмовые лестницы** или **осадная башня — гелеополь**) и рассчитывает часы постройки по лучшему навыку `Engineer` осаждающей коалиции.
  - Во время осады гарнизон блокирован, запасы продовольствия крепости (30 дней у замка, 60 у города) тают.
- **Кооператив и PvP вокруг осады:**
  - Друзья могут подъехать и влиться в осадный лагерь.
  - Защитники (ИИ или другие игроки внутри крепости!) могут устроить вылазку (`Sally Out`), если у осаждающих мало сил или много лучников без прикрытия.
  - Если вражеская армия атакует осадный лагерь с тыла, начинается полевое сражение за снятие осады (с поддержкой вылазки гарнизона).
- **Многофазный штурм на Battle-сервере:**
  - Фаза 1: Штурм стен (с лестницами или толкаемой бойцами осадной башней!).
  - Фаза 2 (при больших гарнизонах): Бой на центральных улицах города.
  - Фаза 3: Финальная схватка с элитной стражей внутри тронного зала / цитадели!
  - По итогам взятия применяются все последствия оригинала: урон процветанию, судьба пленных в подземельях (игрок может освободить пленённых там союзных лордов или друзей!), раздел казны и передача крепости на распределение королю (либо мгновенное основание собственного королевства, если игрок независим!).

---

### 5.9. Наёмничество, вассалитет, маршальство, леди, свадьбы и пиры

- **Контракт наёмника:** заключение месячного контракта с любой воюющей державой, продление, компенсация содержания армии от короны.
- **Вассальная присяга и феоды:**
  - Присяга любому из 6 монархов Кальрадии (или королю-игроку!), получение первой деревни, строительство улучшений (поместье, мельница, сторожевая башня, школа, голубиная почта; в городах и замках — башня для узников и гонцы).
  - Управление гарнизонами своих замков и городов (складывание и забор войск/пленных через серверно-проверяемый интерфейс).
- **Маршальство:** участие в походах ИИ-маршала или победа игрока на выборах Маршала королевства — игрок сам созывает вассалов державы (и ИИ-лордов, и друзей-вассалов!) в военный поход и ведёт объединённую рать на штурм вражеских столиц!
- **Ухаживания, Свадьбы и Пиры (`Feasts`):**
  - Знакомство с дамами на пирах, посвящение побед на турнирах, чтение выученных у бардов поэм (с учётом характера конкретной леди!), благословение отца/опекуна или тайный побег с невестой, дуэли с соперниками (включая соперничество двух игроков за одну невесту!).
  - Свадебная церемония, переезд супруги в замок/город игрока, организация собственных **Королевских Пиров** (заполнение кладовой продуктами, напитками и специями для роста отношений со всеми приглашёнными лордами и друзьями).

---

### 5.10. Собственное королевство игрока, игроки-вассалы и претенденты на трон

- **Королевство игрока (`Sovereign`):**
  - Захват замка/города независимым игроком (или восстание вассала при отказе короля отдать захваченный город) активирует личную державу `fac_coop_kingdom_<i>`.
  - Полное управление двором через Министра: название державы, цвет на карте, базовая культура рекрутов, назначение Маршала, раздача земель, отправка послов к другим монархам (перемирие, торговое соглашение, признание права на трон `Right to Rule`, объявление войны).
  - **Уникальная кооп-фича — Живая Феодальная Иерархия Игроков:**
    - Друзья могут принести вассальную клятву Королю-игроку!
    - Король-игрок жалует друзьям захваченные деревни, замки и города, назначает одного из друзей Маршалом королевства, собирает их на пиры в своей столице — при этом каждый друг остаётся полноценным лордом со своей армией, бюджетом и семьёй!
- **Претенденты на престол (`Claimants`):**
  - Леди Изолла Сунийская, Арва Жемчужная, Летвин Дальнозоркий, Дустум-хан, Князь Вальдым Бастард и Лорд Кастор Велукский доступны в тавернах; игрок (или союз друзей) может поднять мятеж за претендента, переманивать лордов убеждением и довести гражданскую войну до полной победы.

### 5.11. Отчёты, энциклопедия Кальрадии, дипломатические сводки и чат

- Сервер синхронизирует актуальную матрицу отношений всех фракций (войны, перемирия, торговые договоры), владельцев центров и лордов — поэтому тултипы городов на карте, экран **Фракций**, **Персонажей/Лордов** и **Личных отчётов** всегда показывают реальные данные текущего игрока, а не заглушки.
- Мировые оповещения в цветном логе на экране у всех игроков (объявление войн, взятие городов, пленение королей, начало турниров и пиров).
- Многоканальный внутриигровой чат: `[Мир]`, `[Братство / Союз]`, `[Фракция]`, `[Рядом]` и личные сообщения `/w`.

## 6. Умный установщик, атомарный обновлятор и чистый деинсталлятор

Чтобы порог входа для друзей был минимальным («скачал один файл → нажал две кнопки → в игре»), мы разрабатываем собственный легковесный установщик **`WarbandOnlineCoop_Setup.exe`** и деинсталлятор **`WarbandOnlineCoop_Uninstall.exe`**.

### Как работает установка, обновление и удаление:

1. **Автоматический поиск установленной игры:**
   - Сканирует реестр Windows для **Steam** (`Steam App 48700` + парсинг всех библиотек `libraryfolders.vdf` на всех дисках `C:\..Z:\`), **GOG** (`GOG.com\Games\1207660253`), **TaleWorlds Standalone** (`HKCU\Software\MountAndBladeWarbandKeys` и стандартные каталоги `Program Files`, `Games` и т.д.).
   - Если найдено несколько копий — даёт удобный выпадающий список + кнопку `Обзор...`. Проверяет наличие `mb_warband.exe` и `Modules\Native`, чтобы нельзя было случайно установить мод в пустую папку.
2. **Изоляция файлов и криптографический манифест (`install_manifest.json`):**
   - Мод ставится максимально изолированно: сам модуль в `Modules\CalradiaOnline\`, исполняемые файлы WSE2 / лаунчера / супервизора — в выделенную подпапку `CalradiaOnlineRuntime\` (либо строго по списку манифеста), а пользовательские сейвы, настройки и `identity.key` — в отдельную защищённую папку данных.
   - Установщик записывает точный `install_manifest.json`: список всех созданных файлов, папок, ярлыков и их SHA-256 хэшей + версию сборки.
3. **Обновление в 2 клика с полным вычищением старого мусора:**
   - При запуске нового `WarbandOnlineCoop_Setup.exe` установщик видит установленную прошлую версию и автоматически переключается в режим **«Обновить до vX.Y.Z»**:
     1. Проверяет, не запущены ли сейчас процессы игры/сервера, и мягко предупреждает/закрывает их.
     2. Делает резервную копию сейвов мира, профилей игроков, `identity.key` и `coop_settings.ini`.
     3. Читает старый `install_manifest.json` и **полностью удаляет абсолютно все файлы старой версии мода** (чтобы удалённые или переименованные в новом патче скрипты/ресурсы никогда не конфликтовали!).
     4. Распаковывает свежую сборку, мигрирует настройки `coop_settings.ini` (сохраняя пользовательские параметры и добавляя новые ключи по умолчанию) и записывает новый `install_manifest.json`.
4. **100% Чистое удаление (`WarbandOnlineCoop_Uninstall.exe`):**
   - Регистрируется в стандартном меню Windows *«Приложения и возможности / Установка и удаление программ»* и лежит в папке мода.
   - По клику удаляет строго все файлы и папки по `install_manifest.json`, ярлыки Рабочего стола / меню «Пуск» и ветку деинсталлятора в реестре.
   - Имеет аккуратную галочку: `[ ] Удалить также сохранения миров и мой ключ персонажа` (по умолчанию выключена, чтобы при переустановке не потерять прогресс; если включить — вычищает вообще всё под ноль). Оригинальный Warband остаётся нетронутым байт-в-байт.

## 7. Верификация и автотестирование по методологии `coop-anything`

Поскольку мы пишем всю систему целиком до начала ручных тестов в самой игре, критически важно проверять каждый модуль автоматически прямо в процессе разработки. Мы интегрируем лучшие практики и инструменты из `cranebeaker/coop-anything`:

1. **Автономный Python 3 компилятор и статический верификатор Module System (`tools/ms_compiler/`):**
   - Компилирует все 29 таблиц Warband (`.txt`) на любой ОС за считанные секунды без устаревшего Python 2.7.
   - **Статический аудит сетевого протокола:** проверяет каждую пару `multiplayer_message_put_int(..., bits)` ↔ `multiplayer_cur_message_get_int(..., bits)` на совпадение разрядности бит (несовпадение хотя бы на 1 бит в WSE2 ломает весь пакет и роняет клиент).
   - **Аудит синглтон-утечек:** автоматически сканирует скрипты/меню/диалоги на случайное использование одиночных `trp_player` / `p_main_party` / незащищённых `$g_*` в серверном коде.
2. **Headless-симулятор мира и фаззер синхронизации (`tools/sync_sim/` на базе идей `fakeworld` + `fuzz` + `ownership`):**
   - Тестирует на тысячах случайных последовательностей серверную логику инвентаря, торговли, обмена между игроками, распределения лута/пленных, очередей осад и инстансов квестов.
   - Проверяет строгие инварианты: *закон сохранения золота и предметов (нет дюпов и пропаж)*, *один владелец у каждого уникального спутника/феода*, *корректность отката при обрыве связи*.
3. **Встроенный Flight Recorder (`cofr`) и сетевой `chaos`-прокси:**
   - В серверный и клиентский слой сразу закладывается структурированное бинарное/JSON-логирование ключевых транзакций, чтобы на этапе живого тестирования любая ошибка находилась за минуты, а не недели.

## 9. Поэтапный план реализации (Этапы работ)

Мы будем двигаться последовательно сверху вниз, полностью закрывая и покрывая офлайн-проверками каждый этап перед переходом к следующему:

### Этап 1. Фундамент, спецификации протоколов и компилятор Module System
- [ ] Развернуть полную структуру каталогов репозитория и спецификации сетевого протокола (`docs/`).
- [ ] Подготовить базу **Module System (Warband 1.174 + WSE2 1.1.5.4 opcodes)** и написать современный Python 3 сборщик `build_module.py` со встроенным статическим анализатором пакетов и слотов.
- [ ] Заложить пулы сущностей: `trp_coop_hero_0..31`, `fac_coop_player_0..15`, `fac_coop_kingdom_0..15`, константы слотов и единый битовый протокол сообщений клиент ↔ сервер.

### Этап 2. Слой WSE2 Lua, крипто-идентификация без Steam и сохранение мира
- [ ] Реализовать `lua/auth.lua` + генерацию/проверку ключей `identity.key` (независимо от Steam/GOG/Standalone).
- [ ] Реализовать `lua/persistence.lua`: атомарное сохранение/загрузку состояния мира, профилей игроков, отношений, инстансов квестов и предприятий с ротацией резервных копий.
- [ ] Встроить `flight_recorder.lua` для трассировки всех критичных событий.

### Этап 3. Ядро глобальной карты, создание персонажа и Братства
- [ ] Полная кооперативная анкета создания героя, выбор стартового города (включая старт рядом с другом) и выбор знамени.
- [ ] Спавн и синхронизация партий игроков, динамические иконки, разведка (`Spotting`), следы (`Tracking`), скорость (`Path-finding`).
- [ ] Консенсусное управление скоростью времени (`1x / 3x / 5x / Пауза`), режим Лагеря, чтение книг, система Братств, чат и безопасный выход с защитой от лива из боя.

### Этап 4. Боевой конвейер (Карта ↔ Пул Battle-серверов) и все виды сражений
- [ ] Реализовать IPC-связку `ipc_bridge.lua` и протокол запуска/завершения боёв.
- [ ] Полевые бои, пре-батл меню, автобой, отступление, **динамический вход союзников и противников в уже идущий бой (Drop-in Reinforcements)**.
- [ ] Раздельное командование дивизиями каждого игрока в 3D-бою + делегирование командования, камера наблюдения после ранения.
- [ ] Точный расчёт `Surgery`, `First Aid`, `Wound Treatment`, опыта, известности, пленных, персонального трофейного лута, судьбы лордов и кооперативного плена (спасение на карте, выкуп, побег из темницы).

### Этап 5. Инвентарь, отряд, провизия, экономика, города, деревни и турниры
- [ ] Серверно-авторитарный инвентарь, экран отряда (апгрейды + `Trainer`), окно прямого обмена `Player-to-Player Trade`.
- [ ] Потребление и порча еды, боевой дух, дезертирство и еженедельный финансовый бюджет.
- [ ] Живая торговля в городах и деревнях с проверкой цен, покупка цехов (предприятий) каждым игроком, перегон скота, таверны, наёмники, 16 уникальных спутников + офицеры, тренировочные поля, арена и **совместные турниры**.

### Этап 6. Квесты, осады, феодальная политика, свадьбы и собственные королевства
- [ ] Серверный инстанс-движок всех квестов (гильдмейстеры, старосты, лорды, маршал, леди) с поддержкой совместного прохождения.
- [ ] Полный цикл осад (осадный лагерь, постройка лестниц и башен по `Engineer`, голод, вылазки, многофазный штурм и оборона стен игроками).
- [ ] Наёмничество, вассалитет, владение и застройка феодов, выборы Маршала, ухаживания за леди, дуэли соперников, свадьбы и пиры.
- [ ] Основание собственного королевства игрока, двор и Министр, претенденты на престол и возможность принимать других игроков в живые лорды-вассалы своего королевства.

### Этап 7. Нативные C/C++ сервисы, Лаунчер и Установщик «в пару кнопок»
- [ ] Собрать `CoopHostSupervisor` + однопортовый UDP-мультиплексор + клиентский сетевой помощник (кросс-компиляция под Windows через MinGW-w64 + поддержка MSVC).
- [ ] Собрать удобный графический `CoopLauncher.exe` (создание ключа профиля, кнопки «Хостить кампанию» и «Подключиться», настройки мира).
- [ ] Собрать `WarbandOnlineCoop_Setup.exe` и `WarbandOnlineCoop_Uninstall.exe` (автопоиск Steam/GOG/Standalone папки Warband, атомарное обновление с полной зачисткой старых файлов по `install_manifest.json` и сохранением сейвов, 100% чистое удаление).

### Этап 8. Полный прогон офлайн-автотестов и фаззера синхронизации
- [ ] Прогнать полный пакет тестов (`test_protocol_bits.py`, `test_singleton_leaks.py`, `test_sync_sim.py`, `test_installer_logic.py`) и собрать готовый релизный дистрибутив для первого живого теста на ПК.
